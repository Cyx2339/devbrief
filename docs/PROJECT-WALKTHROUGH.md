# DevBrief 架构与实现

## 这个项目解决什么问题

技术团队收到的客户反馈和需求讨论通常缺少复现条件、责任人、边界或验收方式。DevBrief 将原始文本整理成六类信息：标题、摘要、已知事实、待确认信息、建议行动、建议完成条件。所有结果可以编辑后导出。

本项目基于 pdsuwwz/chatgpt-vue3-light-mvp 二次开发，原项目的 Vue 3 工程、路由、基础样式与聊天能力保留。新增工作台按“输入 / 服务 / 结构校验 / 编辑 / 本地保存”分层。它没有新增 RAG、向量数据库或 Agent 工具调用。

## 请求流程

1. 前端校验模板、至少10个有效字符、最多12000个字符和补充背景长度。
2. 规则演示：本地摘录原文事实，给出固定的场景建议；明确标注“规则演示”。
3. AI服务：前端 POST `/api/briefs/stream`，请求体只有模板、原文和补充背景。
4. FastAPI 在服务器读取模型地址、模型名和密钥，发起 OpenAI-compatible 流式请求。
5. 前端消费 `status`、`delta`、`result`、`error` 事件；供应商格式只由服务端处理。
6. 完整JSON通过Pydantic校验后才发送result，前端再次检查结构，之后创建历史记录。
7. 用户编辑结果，350ms防抖保存；复制和导出始终读取当前编辑内容。

## 为什么重新定义流式契约

原项目是通用聊天渲染，本工作台需要一份有固定字段的工单。部分JSON不能当成完整工单展示，也不能提前保存。新模块沿用“协议处理与UI分离”的架构思路，采用自己明确的事件契约，避免让工作台解析供应商专有字段。

字节流中的chunk不等于SSE事件。`readSSE`使用每次请求独立的TextDecoder和缓冲区，正确处理中文UTF-8被拆开、CRLF换行、一个chunk内多个事件，以及跨chunk半包。未以事件边界结束的内容会判定为中断。

## 停止、失败与历史

- AbortController可以在响应头尚未返回时停止fetch；已有reader也会被取消。
- 已停止和失败的运行均不新增历史工单。
- 模型超时、限流、无密钥、无完整结果均有明确错误，不静默切换为模拟结果。
- 历史保存只在完整结果或编辑有效时执行；空间不足会提示导出。
- 历史格式损坏时不覆盖原值，以保留用户恢复数据的机会。
- 演示结果与真实模型结果保留来源标识，服务端mock也不会被标为AI结果。

## 设计讨论

1. SSE事件为什么不能按网络chunk直接JSON.parse？
2. 为什么“停止显示文本”和“停止网络请求”是不同的事情？
3. 为什么JSON格式校验通过仍不代表内容事实正确？
4. 为什么密钥放在VITE_环境变量中仍可能暴露，而本模块改放服务端？
5. 编辑后的草稿如何保存？换一台电脑为什么没有历史？
6. 这个项目复用了哪些上游能力，自己新增了什么？

## 实现范围

新增模块覆盖工单整理、结果校验、编辑、本地历史和导出。上游通用聊天页面保留。当前不包含真实模型效果评估、团队协作、跨设备同步或外部工单平台写入；后续可在现有边界上逐步扩展。
